**Scanner note.** Trinity's section filter
(`src/mem/section_filter.cpp`) skips only a section named *exactly* `.debug`
that lacks `IMAGE_SCN_MEM_EXECUTE`. This build has **no** such section: the
debug-ish section is named `.debug$P`, so all 12 sections are scanned. A future
PE that renames it to `.debug` would silently change what the locator scan can
see, and stale machine-code bytes in a scanned non-executable data section can
produce false AOB matches. Locator uniqueness below was therefore measured over
**all 12 sections**, which is the conservative (matching) case.

## Change summary vs the previous snapshot

The previous documented snapshot was PE 2850 (see
`docs/superpowers/plans/2026-09-11-pe-2850-*`). For the Travel feature the
important change is that the historical three-argument
`sub_505140(ignored, sceneId, nodeIndex)` contract (`kSig_TravelToNode`) no
longer applies: PE 2944 splits the feature into a map-UI selection gate and a
separate final dispatcher with a four-argument ABI (`R9D` mode). Trinity's
PE 2944 branch resolves **both** locators and binds its native call to the
dispatcher. See `dossiers/travel.md`.
